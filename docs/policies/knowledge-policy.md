# Knowledge policy

**Version:** 0.1.0  
**Owner:** Adapter maintainer  
**Review:** on every behaviour/configuration change and at release  
**Enforcement:** knowledge-record and manifest validation delivered by `TR-M03`

Every active adapter has a concise guide covering purpose, value, prerequisites, configuration, operations, quick start, expected outputs, limitations, troubleshooting, and safe use.

Usage learning has two separate labels:

- **validated usage:** date, context, adapter version, observed outcome, constraints/lesson, and safe evidence reference;
- **suggested use:** a possible application with assumptions and validation still required.

Suggested use must never be written as a proven result. Guides and records must not contain secrets, customer data, or unsupported claims. A material behaviour, safety, or limitation change requires corresponding guide updates before release.
